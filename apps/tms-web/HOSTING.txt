---- Luna support chatbot ----
UI: floating ball in apps/tms-web (index.html #lunaRoot + styles.css + app.js).
Visible on the login screen and after sign-in.
API (Cognito optional — same paths work as guest with rate limits):
  POST /support/luna/chat
  POST /support/luna/handoff
    Body requires contactName + contactEmail (light email format check).
    Prefill from Cognito when signed in; both fields remain editable and mandatory.
  Guest (no Bearer / invalid JWT): treated as unauthenticated support chat.
    Rate limits (per Lambda instance, keyed by X-Forwarded-For):
      chat ~30 / 15 min, handoff ~5 / hour.

OpenAI key (NEVER in the frontend / Netlify env):
  Live (preferred): AWS Secrets Manager → secret created by CDK as TmsLunaOpenAiSecret
    (stack output TmsLunaOpenAiSecretArn). Open the secret → Retrieve secret value → Edit →
    paste the plain API key string (sk-...) replacing REPLACE_ME_IN_SECRETS_MANAGER.
    Optional one-time seed on deploy: cd infra && npx cdk deploy -c openaiApiKey=sk-...
    (value is ignored on later deploys once the secret already exists).
  Local: set OPENAI_API_KEY in the shell (or .env loaded by your process) before
    npm run tms:local
  Optional: OPENAI_MODEL (default gpt-4o-mini), LUNA_SUPPORT_EMAIL
    (default moshe@advancedautomations.net)

Handoff email:
  Uses existing TMS SES mailer (TMS_FROM_EMAIL / ALERT_FROM_EMAIL).
  Sends to LUNA_SUPPORT_EMAIL. If TMS_FROM_EMAIL is empty, local MemoryMailer logs only.
  Live stack already sets TMS_FROM_EMAIL from alertFromEmail (moshe@advancedautomations.net
  in cdk.json) and grants ses:SendEmail — ensure that From identity is verified in SES.

---- Timesheet principal e-sign (SignNow) ----
Client vendor is **SignNow** (not DocuSign). UI and API messages say SignNow.
Until a SignNow REST integration exists, "Send timesheet" emails the branded PDF via SES.
POST /webhooks/esign remains available for a future SignNow completion hook.
Legacy AWS secret construct TmsDocuSignSecret is unused by the send path.

---- HHA transfer (lock / sign / admin "Send to HHA") ----
Live TmsApiFn must have:
  HHA_USE_MOCK=false
  HHA_SECRET_ARN=<same imported HhaSecret as pipeline processors>
  HHA_USE_PRODUCTION=true
  HHA_ALLOW_PRODUCTION=true
  HHA_PRODUCTION_BASE_URL=https://app.hhaexchange.com/Integration/ENT/V1.8/ws.asmx

Secret JSON keys used for SOAP (already shared with processors — do not invent new creds):
  appName, appSecret, appKey, baseUrl / productionBaseUrl
  (apiKey may be PLACEHOLDER — SOAP path does not need it)

Optional local override to force mock on Lambda: TMS_HHA_MOCK=1
Local `npm run tms:local` always uses MockHhaClient.

Verify after deploy:
  aws lambda get-function-configuration --function-name <TmsApiFn> \
    --query "Environment.Variables.[HHA_USE_MOCK,HHA_SECRET_ARN]"
  CloudWatch log line: "[tms-hha] Real HHA client ready"
  Sign/lock a week or admin POST /weeks/{id}/hha → transfer status confirmed (not mock ids).
